## 星うさぎ画像の調査

正式な透過PNGは4枚とも存在し、`js/config.js` の参照先と実ファイル名は一致していた。
観覧車は `assets/characters/star-bunny-ferris-wheel.png`、ミニトレインは `assets/characters/star-bunny-train.png`。
案内欄と正解時のお祝い欄は、同じ施設別画像を使用する。

4枚のPNGについて、署名・全チャンクのCRC・IDAT展開・824×753pxの寸法を確認し、破損は検出されなかった。観覧車画像は画像ビューアーでも内容を確認した。
画像の生成・加工・差し替えと、設定の画像パス変更は行っていない。

旧処理では一度読み込みに失敗すると、同じ画像の再表示要求が早期returnされ、再訪しても代替文のままになることがコード上で確認できた。
また、同じimg要素のイベントハンドラーを施設ごとに上書きしていたため、現在の要求と古い要求を個別に識別できなかった。
今回、画像ごとの読み込み要求を保持し、現在の要求が成功したときだけ完成画像を表示する。失敗時も代替案内とゲーム操作を維持し、同施設の再訪時には再試行する。

依頼にあった公開環境での画像欠落そのものは、ブラウザー操作ツールの停止により再現できていない。通信失敗など、最初の読み込み失敗が発生した要因は未特定。

## 確認結果

本体はHTML/CSS/JavaScriptの静的構成で、ビルド工程・ビルドコマンドはない。既存の `node scripts/check.mjs` を実行して全項目合格。

- JavaScript全10ファイルの構文確認。
- 推理4問の全順列、線路第1問の全32,768盤面、第2問の全経路、全6問の正解・不正解・未完成・重複・ヒントの整合。
- 途中配置・回転・ヒント、全6問クリア、エンディング、再プレイ、破損22ケース、保存禁止・容量不足、初期化、他の保存キーの保護。

追加で一時的なLinkeDOM環境を用意し、実際の `index.html` と本体JS5ファイルをVM内で読み込み、DOMイベントによる統合確認を実施した。本体へのライブラリ追加・依存関係変更はない。

| 検収項目 | 今回の結果 |
| --- | --- |
| 開発中の表記・操作がない | DOM上でタグ・DEV操作の不存在と、プレイヤー向け本文にDEV・最終検収版・準備中・配置確認用がないことを確認 |
| 観覧車・ミニトレインの画像 | 開始前・ヒント・再開・正解後の案内欄、お祝い欄で、完成画像の参照と表示状態を確認。一時失敗後の同施設再訪、施設切り替え後の古い成功/失敗通知、キャッシュ即時完了も合格 |
| 全6問の進行 | 開始、選択・回転、ヒント、答え合わせ、第2問の解放、復活数0→1→2→3を実イベントで確認 |
| エンディング | 未解放の直接アクセスを防止。全復活後の解放・到達・夜景画像参照・到達記録保存・再開を確認 |
| セーブ・再開・リセット | 各問の配置完了後に保存データを使って再起動し、答え合わせまで継続。リセットの取消は記録維持、確定後は初期状態で再開。他の保存キーを維持 |
| 体験版に変更がない | 正式版の作業フォルダーと正式版リポジトリだけを使用。体験版への書き込み・公開操作なし |

DOM統合確認では画像イベント・通信・スクロール・ダイアログを模擬しており、実ブラウザーの描画確認には相当しない。
ローカルHTTPサーバーの起動は成功したが、in-app browserはlocalhost接続がタイムアウト。EdgeのComputer Useは「現在のブラウザーURLを十分な確度で判定できない」としてツール側で停止した。
したがって、修正後の実ブラウザーでの画像表示・PC/スマートフォンの見た目・実ブラウザー終了後の再開は未確認。PRの最終検収で確認する。
